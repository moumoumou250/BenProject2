# 0005 规则文件有行长预算

- Status: accepted
- Date: 2026-11-18

## Context

`AGENTS.md` 是生成物（`ben init` 写入，`ben/commands/setup.py` 的 `_AGENTS_SPEC`
是唯一来源），被每轮对话注入上下文。它的历史版本一直保持在 40–50 行，这是它
有效的原因：每条规则都被人真的读过。

规则文件的失效方式不是写得不好，而是**只增不减**。每次事故后加一条，两年后
没人读，规则变成安检门上的贴纸。

## Decision

`AGENTS.md` 上限 60 行。超了必须先删一条再加一条。新增规则要能回答一个问题：
「这条能不能变成 `arch_check` 里的一个 check？」能就写成检查，不能才留文字。

## Consequences

- 代价：加规则时要和旧规则竞争，这是有意的摩擦。
- 收益：注入上下文的大小有上界；规则集合始终小到可通读。
- 注意：预算作用在**生成物**上；`ben init` 写出的文件首行带
  `<!-- generated by ben -->` 标记，手写文件不受此限（因为手写规则通常更克制，
  且没有生成器替它把关）。

## Enforced-by

`scripts/ci/arch_check.py --check agents_budget`

判据：若 `AGENTS.md` 首行是生成标记，则行数 ≤ 60（`RULE_BUDGET`），否则违规。
