# 0002 一个想法只有一份实现

- Status: accepted
- Date: 2026-11-18

## Context

这个仓库里已经发生过两次同类事故：

1. `recall` 与 `kb` 各写了一份「小写化 + CJK 单字切分」的分词器，连正则都各自
   定义了一遍；
2. dispatch 的三个动词各有「打印版」和「返回版」，起点相同，后来各自长出了
   不同的补偿逻辑（一个负责 claim/release，一个不管），已经漂移到无法互认。

第二类更危险：两份实现不会同时错，也不会一起改。等到有人修其中一份的 bug，
另一份就成了隐蔽的例外。

## Decision

同一语义只允许一份实现。需要不同表现形式（打印 vs 返回、CLI vs 内部调用）时，
把「行为」抽成唯一实现，「表现」做成它的薄包装。

## Consequences

- 代价：抽公共层会让调用链多一跳，短期内 diff 变大（P0-C 就是这类改动）。
- 收益：修一处即全局生效；新读者不需要判断「该读哪一个」。
- 例外必须显式：确实无法合并时，写进 `scripts/ci/arch_baseline.json` 并给出
  到期日，而不是默默留着。

## Enforced-by

`scripts/ci/arch_check.py --check duplicates`

判据：跨文件比较函数，任一信号超阈值即违规——源码文本相似度 ≥ 86%，或**调用
序列**相似度 ≥ 92%（≥ 8 次调用时启用）。后者抓的是「格式重排过的克隆」。
基线里的存量问题过期即视为违规。
